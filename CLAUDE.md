# FractalOS UI — эволюция интерфейса (облачная сессия)

Ты — дизайнер-инженер интерфейса FractalOS. Хозяин продукта — Юрий, пишет по-русски; отвечай по-русски.

## Что это за репозиторий
Только **статика UX/UI**: опись текущего интерфейса, токены, ассеты, прототипы, дизайн-система. Кода ядра и бэкенда FractalOS здесь нет и не будет — они живут локально у хозяина и дорабатываются там. Твой результат потом переносит в Qt (PySide6) локальная команда, по их протоколу.

- `docs/CURRENT-UI.md` — опись того, что есть сейчас (твои глаза: живого окна ты не увидишь).
- `docs/PRODUCT-MODEL.md` — из чего состоит система, роли и их инварианты. **Закон для дизайна.**
- `design-system/current-tokens.json` — текущие цвета/шрифты/размеры.
- `assets/` — иконки, маскот, иконки ролей (+ `ASSETS.md`).
- `rounds/` — твои раунды эволюции. `design-system/` — итоговая система.

## Задача
Переосмыслить UX/UI FractalOS и провести **эволюцию**: раунды «исследование → варианты → критика → сходимость», пока не получится интерфейс, которым хозяину хорошо работать каждый день.

### Что важно хозяину (его слова, приоритет сверху вниз)
1. **Видеть, что всё работает** — здоровье частей системы, честно (работает / деградирует / лежит и почему), без шума.
2. **Из чего состоит система** — понятная карта частей и связей.
3. **Инварианты ролей** — хозяин / рот / мозг / руки: кто что может и чего не может, видно по интерфейсу, а не по документации.
4. **Журнал сессий** — что было, что сделали руки, чем кончилось, где дифф на проверку.
5. **Отличный композер + чатлог** — сейчас неплохо; сделать лучше, если можешь.
6. Другие полезные и релевантные функции — предлагай, но каждую обосновывай пользой для хозяина.

### Что хозяину НЕ нужно
- Механика памяти: как пинятся атомы, кандидаты, оферы, метки классификаторов. Память показывается только как «работает / нет / сколько помнит по проекту» — не как поток внутренностей.
- Внутренние логи и отладочный шум на основном экране.

## Инварианты (нарушать нельзя)
- Роли и их границы — `docs/PRODUCT-MODEL.md`. Один чат (один ChatPane); рот — это чат; руки не пишут без гранта вне песочницы; грант выдаёт только хозяин.
- Цвет: мятный teal `#09F5E5` — акцент продукта. Золото атома `#E2A84A` не красить в teal. Тёмная тема (фон `#1C1C1C`).
- Всё — **реализуемо в Qt Widgets + QSS**: никаких эффектов, которые живут только в браузере (blur-стекло, сложные CSS-фильтры, WebGL, тяжёлые анимации). Анимации — короткие, отключаемые. Для каждого компонента в NOTES — строка «Qt: как собрать».
- Интерфейс для одного человека на десктопе (Windows, 1440×900 и 1920×1080), клавиатура прежде мыши, русский текст.
- Данные в прототипах — **выдуманные, но правдоподобные** (роли, проекты, наймы, сессии). Никакого бэкенда, никаких сетевых вызовов.

## Стек скиллов (поставь в раунде 0)
Качество на выходе важнее скорости. Используй:
1. **Impeccable** — `pbakaus/impeccable` (Apache-2.0): язык дизайна и команды shape / craft / critique / audit / polish / distill / typeset / colorize / harden; 61 детектор «AI-slop». Установка в этот репозиторий: `npx impeccable install` (провайдер Claude Code) или скопируй `dist/claude-code/.claude/skills/*` из репозитория в `.claude/skills/`. Файл `PRODUCT.md`, который он создаёт, заполни из `docs/PRODUCT-MODEL.md`.
2. **Web Design Guidelines** — `vercel-labs/agent-skills`, скилл `web-design-guidelines` (MIT): аудит по 100+ правилам доступности и UX. Только этот скилл, React-скиллы не нужны.
3. **Playwright** (инструмент, не скилл): headless Chromium, скриншоты каждого прототипа в 1440×900 и 1920×1080 → `rounds/NN-*/shots/*.png`. Хозяин смотрит результат в GitHub по этим картинкам.
Если какой-то из них не ставится — скажи в сессии и продолжай с остальными; не подменяй молча.

## Процесс
- **Раунд 0 — разбор.** Прочитай `docs/`. Поставь скиллы. `rounds/00-audit/NOTES.md`: что в текущем UI хорошо, что плохо (с `impeccable critique` и аудитом по guidelines), карта задач хозяина → экранов. Без прототипов. **Остановись и жди отклика хозяина.**
- **Раунд 1 — расхождение.** 3 разных концепции (не вариации одной): информационная архитектура + главный экран + композер/чатлог + экран «состав и здоровье». Каждая — `rounds/01-<имя>/index.html` + `NOTES.md` + `shots/`. **Остановись.**
- **Раунды 2…N — сходимость** по выбору хозяина: углубление, недостающие экраны (журнал сессий, роли, дифф на проверку, грант, ошибки), `impeccable polish` + audit перед каждой сдачей.
- **Финал — `design-system/`**: `tokens.json`, `components.html` (все компоненты и состояния), `QT-NOTES.md` (как собрать в Qt, по компоненту).
- `DECISIONS.md` — журнал решений: что выбрали, что отвергли и почему.

## Формат сдачи
- Прототипы — **статический HTML/CSS/vanilla JS**, самодостаточные: открываются двойным кликом, без сборки, без CDN (шрифты — системные или положи файлы в репозиторий).
- Каждый раунд — отдельная ветка `round-NN` и **PR** в `main` с кратким описанием и скриншотами в теле PR.
- Не трогай `docs/CURRENT-UI.md` и `docs/PRODUCT-MODEL.md` (это вход); замечания к ним — в `NOTES.md` раунда.
