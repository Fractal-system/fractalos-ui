# FractalOS — опись текущего UI (снимок для облачной эволюции)

Это **опись того, что есть сейчас**, снятая с живого кода Qt/PySide6
(`C:\FractalOS\app\*.py`). Кода здесь нет — только поверхности, тексты,
состояния, размеры и потоки. Всё, что хозяин видит на экране, описано по
файлам и строкам, чтобы дизайн опирался на факт, а не на воспоминание.

Обозначения: `app/<файл>.py:<строка>` — источник. Размеры — пиксели Qt
(логические px, DPI-масштабирование системное). Тексты даны дословно по-русски,
как в коде.

**Два состояния окна.** Окно живёт в одной из двух «оболочек»:

1. **Сплеш** (`Gate`) — окно 940×828, без заголовка и рельса. Хозяин выбирает
   «Продолжить» или «Новая сессия».
2. **Рот** (`mouth`) — рабочий режим: заголовок + чатлог + композер + рельс.
   Переход между ними анимируется выездом рельса, 280 мс, `OutCubic`
   (`app/theme.py:159`, `app/window.py:6515-6565`).

Корневая раскладка (рот открыт):

```

└── QVBoxLayout (spacing 0)

    └── body (QHBoxLayout, spacing 0)

        │            ProcessDock (22px) / BtwPane / ghost (16px)
        └── _RailHost (QWidget, фиксированная ширина)
            └── Rail              ширина = rail_width(inner), см. ниже
```

Источник раскладки: `app/window.py:778-907`; HUD-оверлеи: `app/window.py:6273-6338`.

**Ширина рельса** — функция от ширины окна (`app/theme.py:178-189`):
- базовая `MASCOT_RAIL + 2·RAIL_PAD` = `220 + 44` = **264px**;
- нижняя `MASCOT_RAIL_MIN + 2·RAIL_PAD_MIN` = `160 + 20` = **180px**;
- при тесном окне рельс ужимается (сначала паддинг, потом дух), **но рот
  никогда не отдаёт ниже `MOUTH_MIN = 640`**: `rail_w = max(180, min(264, inner − 640))`.
- Рельс никогда не растёт сверх базы при расширении окна — лишняя ширина уходит рту.

**Сплеш-раскладка** (`Gate`, `app/chrome.py:205-468`):

### 1.2 Рельс (Rail) — правая колонка

Размер: ширина 180…264px (см. выше), отступы `RAIL_PAD=22` по бокам и
`SPACE_MD=12` сверху/снизу, spacing 4. Фон = `BG` (тот же, что чатлог: шва нет).
Источник: `app/rail.py:578-1032`.

Сверху вниз:

1. **Три роли** — строки `44px` каждая, воздух между ними 10px
   (`app/rail.py:643-647`):
   - глиф 44×44 (штамп PNG или нарисованный), затем метка роли, затем сегмент
     провайдера `Flash | Grok`:
     - `Рот:` — всегда включён, сегмент активен (`app/rail.py:617-623`);
     - `Мозг:` — переключатель питания + сегмент, выкл → сегмент серый
       (`app/rail.py:625-632`);
     - `Руки:` — переключатель питания + сегмент (`app/rail.py:634-641`).
   - Активная роль: метка `CYAN`; выключенная: `FG_FAINT`.
     Активный провайдер: `CYAN` + подчёркивание; неактивный: `FG_DIM`.
2. **Зона «Внештат»** (`Учитель:`) — **скрыта** (`wave130`,
   `app/rail.py:656-664`); виджет есть, на экран не выводится.
3. **Секция `fractalmem`** — золотой заголовок, затем 4 переключателя
   (`app/rail.py:672-684`):
   `Слой` · `Подача` · `Обучение` · `Горячая память`
   (строка 24px; активный — `[Название]` + CYAN, неактивный — просто название FG_DIM).
4. **Секция `сессии`** — заголовок и список **скрыты** (`self.sessions.hide()`,
   `app/rail.py:701-706`, `setVisible(False)` `app/rail.py:1459`); полный список —
   только в диалоге «сессии». Строка текущей сессии `QLabel#sessionNow` тоже
   **скрыта** (`app/rail.py:711`).
5. **Шкала контекста** (`_ContextFill`, `app/rail.py:189-245`) — 8px высотой,
   скрыта, пока ACP не назовёт реальное `contextWindow`. Цвет: CYAN <80%,
   GOLD ≥80%, RED ≥92%. Tooltip: `контекст рта · {used} / {window} · {pct}%`.
6. **Компактный журнал runtime** (`OpsLivePanel`, `app/ops_live.py:125-242`,
   вставлен на `app/rail.py:721-737`) — высота 220px, всегда виден:
   - голова: строка-сводка (`summary_line`), по умолчанию `runtime`;
   - список действий: `{время} · {вид} · {текст}` (вид: `hygiene`/`hire`/`research`/`ops`);
   - подвал: `обновлено {ЧЧ:ММ}`;
   - кнопка `×` (22px), tooltip «скрыть лог»;
   - обновление по таймеру 4 с и по изменению файлов.
7. **Секция `навигация`** — **скрыта целиком** (`app/rail.py:739-803`):
   заголовок, `navPath` («клик по пути в чате»), кнопки `папка` / `файл`.
   Клик по пути теперь даёт всплывающую полосу в чатлоге (см. 2.2).
8. **Секция `лаборатория`** — золотой заголовок + `LabMini`
   (`app/rail.py:805-815`, `app/labmini.py`):
   - список lab-проектов; у каждого: маркер `>` (OWNER, только у текущего) +
     имя проекта (кнопка, 11px, вес 600; текущий — OWNER) + `[инфраструктура]`
     (10px, FG_FAINT, tooltip «инфраструктура / карта модулей · {имя}»);
   - если проектов нет — `нет lab-проектов в config` (FG_DIM);
   - минимум высоты блока 72px.
9. **Растяжка**, под ней (если `SHOW_MASCOT=True`) — дух 220×220.
   Сейчас **выключен**: `theme.SHOW_MASCOT=False` (`app/theme.py:119`).

> **Важно для дизайна:** рельс — это, по сути, «панель ролей + память + журнал
> runtime + лаборатория». Несколько секций в коде есть, но на экране скрыты;
> это видно в описи как «выключено», а не как «нет».

### 1.3 Чатлог (ChatPane)

`QTextEdit` только для чтения, растягивается на всю оставшуюся площадь.
Фон `BG`, шрифт `Cascadia Mono` 12pt, `documentMargin = 30px`
(левый гуттер под метки и мини-маскота). Источник: `app/chatpane.py:714-752`.

Внутри — богатая лента (markdown → документ), но **не** веб:
- **Ход хозяина**: метка `❯ ` цвета CYAN + тело **пурпуром OWNER `#9B59D0`**
  (каждый символ, включая `code` и **bold**), подложка `CHAT_USER_WASH`
  `rgba(155,89,208,0.07)`; при включённых метках — `ЧЧ:ММ` после метки
  (`app/chatpane.py:1240-1246`, `_stamp` `app/chatpane.py:1061-1070`).
- **Ход рта**: тело FG, без метки; подложка кодовых блоков
  `rgba(9,245,229,0.08)`; подсветка синтаксиса 13 токен-ролями
  (`app/chatpane.py:244-259`, палитра в `theme.py`).
- **Живая мысль**: строка-заголовок `▏ thinking …  [стоп]` (FG_DIM), тело —
  FG_FAINT, первые 12 строк, далее `▏   … развернуть`
  (`app/chatpane.py:84`, `app/chatpane.py:1840-1865`). Клик — развернуть.
- **Карточка инструмента**: `▏ {имя}  {глиф}` + краткий аргумент (FG_FAINT).
  Глифы: `○` чтение, `›` запуск, `✎` правка, `✓` успех (GREEN), `✖` провал
  (RED), `◌` в работе (FG_DIM). У живой карточки — хвост `[стоп]` (GOLD).
  (`app/chatpane.py:71-83`, `app/chatpane.py:1781-1838`).
- **Трасса действий**: `▏ трасса · {n}  {итоги}`, при переполнении
  `▏   … ещё {k}`, затем строки с глифами и `ms`; для правок — мини-дифф
  в ```` ```diff ```` с покраской `+`/`-` (`app/chatpane.py:1966-2027`).
- **Заметка окна**: глиф `ℹ` + текст FG_FAINT (`app/chatpane.py:1776-1779`).
- **Процесс памяти/журнала**: глиф `· ` CYAN_DIM + текст тона
  good/bad/warn/on/dim/faint (`app/chatpane.py:1345-1379`).
- **Присутствие учителя**: `✦ ` цвета PARTNER + одна строка статуса
  (`app/chatpane.py:83`, `app/chatpane.py:1442-1447`).
- **Расписка найма** (`append_receipt`, `app/chatpane.py:2054-2144`) — ключевая
  карточка итога:
  - заголовок: `✓ Готово — подтверждено` (GREEN) /
    `▲ Исполнитель сообщил о готовности — не подтверждено` (GOLD) /
    `✖ Работа не дошла` (RED);
  - хвост: `· {вид} {sid8}` и при провале `· rc={код}` (FG_FAINT);
  - `почему: {причина}` (при неподтверждённом/провале);
  - `done` — строкой FG_DIM;
  - список EXPECT: `✓`/`✖` + путь/текст (до 8, обрезка 120 симв.);
  - `изменены:` + до 6 строк `✎ {файл}`; если найм зелёный и файлов нет —
    `изменённых файлов в ленте нет`;
  - при провале: `хвост лога` (RED) + до 5 строк;
  - `next_action` — CYAN (или GOLD), если задан.

**Клик и меню в чатлоге** (`app/chatpane.py:1669-1712`, `1714-1760`):
- клик по `[стоп]` → прервать ход;
- клик по `thinking …` / `… развернуть` → развернуть мысль;
- клик по строке учителя → чип учителя;
- клик по пути (Windows, `\\…`, `app\…`) → всплывающая полоса:
  путь + `[папка]` + `[файл]` на подложке `rgba(155,89,208,0.12)`
  (`app/chatpane.py:1096-1160`);
- клик по обычному ходу → выбрать ход (1px полоса LINE слева);
- правый клик по ходу → нативное меню **`Копировать`** · **`Откатить сюда`**
  (`app/chatpane.py:1715-1752`).

## 4. Потоки — как их видит хозяин

### 4.1 Обычный Enter (разговор со ртом)

1. Хозяин печатает. Плейсхолдер поля заранее говорит, кто ответит — живая
   строка заявки (`app/slot_matrix.py:375-379`):
   - `Напишите задачу · Enter — Grok`;
   - `Напишите задачу · Enter — Flash (запасной)`;
   - плюс хвосты: `· «найми …» — поручит исполнителю`, `· /btw — вопрос в сторону`.
   Tooltip CTA: `Отправить Grok · Enter · Grok сам планирует сложное · побочные вопросы — /btw` и т. п.
2. `Enter` → `_emit_send`: поле очищается, текст уходит в окно
   (`app/composer.py:813-831`).
3. Окно выбирает поверхность: DSH-эпизод → DSH; живой Flash-чат → Flash;
   `mouth=flash` → Flash-чат; живой ACP → ACP; иначе — поднимает рот и ставит
   сообщение в очередь (`app/window.py:3638-3686`).
4. В чатлоге появляется ход хозяина: `❯ ` CYAN + пурпурное тело.
5. Идёт ход: `▏ thinking …  [стоп]` и/или карточки инструментов
   (`▏ имя  ◌` → `✓`/`✖`), трасса.
6. Ответ рта — обычным FG; по завершении CTA возвращается к «отправить».
7. Пока ход идёт, Enter не теряется: Grok-ход — сообщение в очередь
   (`app/window.py:3612-3623`), Flash — свой стоп.
8. Если память что-то подложила, после хода появляется заметка
   `память: {N} {слово} — /why покажет причины` (`app/window.py:3721-3733`).

**Состояния CTA** (`app/composer.py:774-805`): норма — мятная заливка и глиф рта;
занято (Flash) — «стоп» с золотой рамкой; занято (ACP) — остаётся «отправить»,
tooltip `в очереди · Enter`; ошибка рта — заметка в чатлоге (см. 4.6).

### 4.2 Найм рук

Развилка задаётся словами хозяина и режимом плана (`app/window.py:4097-4195`).

**A. `«найми …»` / `/plan <текст>`** — прямой найм:
1. Окно решает, что это найм, и проверяет слот рук (`hands_on` +
   провайдер). Слот выключен → заметка `руки выкл — слот найма не запущен`
   (`app/window.py:4800-4803`).
2. Пул параллельных наймов: свободен — старт; занят — `найм: пул занят
   (max_parallel_hire=N) — в очереди` (`app/window.py:4839-4863`).
3. Параллельный лейн: `параллельный найм · lane {N} (своя лента hire:<sid>#N,
   лог/бриф изолированы)` (`app/window.py:4871-4879`).
4. В чатлоге: `ℹ Исполнитель начал работу` (`app/window.py:4168`).
5. Прогресс: карточки инструментов и трасса; живой шаг — в `ProcessDock`.
6. Итог — **карточка расписки** (см. 1.3): `✓ Готово — подтверждено` /
   `▲ … не подтверждено` / `✖ Работа не дошла`, со списком EXPECT,
   изменёнными файлами и `почему`.
7. Если работа не доделана — в композере появляется кнопка
   `повторить найм` (tooltip «только если работа не дошла: тот же бриф, тот же hire.py»).
8. Ход рта после найма короткий: окно говорит рту
   «Руки уже запущены. Коротко подтверди хозяину» (`app/window.py:4170`).

**B. `/plan` (без текста)** — только режим плана: переключается `режим плана`
(`app/window.py:3179-3191`), найма нет.

**C. Мозг → руки** (`brain_then_hire`):
- при Grok-рте и той же сессии — `ℹ Готовлю задание для исполнителя…`,
  бриф от самого Grok;

### 4.3 Мозг

- Клик по метке `Мозг:` — вкл/выкл слота (`руки`/`мозг` выкл → заметка
  `мозг выкл` / `руки выкл: нет hire`).
- Клик по сегменту `Flash|Grok` — сменить мозг. Если рот = Grok, мозг
  становится Grok и это сказано: `рот Grok ⇒ мозг Grok, одна сессия`.
- Деградация честная: живой мозг и «желаемый» расходятся — окно пишет
  `мозг: Flash (Grok down/quota) · wish=grok` и одновременно заметку в чатлог
  (`app/roles.py:58-66`, `app/window.py:4885-4891`, `app/window.py:8542-8577`).
- Падение модели-мозга: `мозг Grok нет — отчёт хозяину, найм не запускаем`.

### 4.4 Грант `/approve`

1. Хозяин пишет `/approve` (или `/write`) → в чатлоге и заметке появляется
   статус гранта (`app/window.py:2818-2820`, `app/approve.py`).
2. `/approve <минуты>` — грант на N минут (по умолчанию `DEFAULT_MINUTES`);
   `/approve off` — снять; `/always-approve` (`/yolo`) — на сессию.
3. Длинный грант спрашивает подтверждение: `QMessageBox` **Always-approve**,
   текст `Выдать always-approve на сессию? Запись без подтверждений ~N ч (до конца
   сессии). /approve off снимает.`; по умолчанию — «Нет».
4. Когда руки упираются в песочницу, в чатлоге снизу всплывает полоса
   гранта: причина + `разово` `на сессию` `нет`; в чатлог идёт
   `approve · запись вне песочницы: {причина}`.
5. Ответ хозяина — единственный способ открыть запись. Рот/руки себе грант
   не выдают (`/always-approve` описан в меню как ОПАСНО).
6. При мягком ACL кнопок гранта нет вообще — окно просто пишет статус
   (`app/window.py:2402-2408`).

## 7. Сводка для дизайна: что здесь сильное и что рвётся

**Сильное (сохранить):**
- Один чат = рот; второго чата нет — это соблюдено буквально.
- Чатлог — терминальная лента с честными состояниями `◌ ✓ ✖ ✎ ▲ ℹ` и распиской
  найма как отдельной карточкой; хозяин читает статус по глифу, не по цвету.
- Композер честно говорит, кто ответит (плейсхолдер = живая заявка Enter).
- Полоса памяти `◇` не занимает место, когда нечего сказать (высота 0).
- Все данные для «здоровья системы» уже есть (`modeldown`, `spend`, `writer_lock`,
  `JOURNAL.md`, `dispatch/`) — экран можно собрать, не изобретая.

**Рвётся (кандидаты на переосмысление):**
1. **Строки статуса нет.** `Rail.set_note` — мёртвый канал: ~150 сообщений
   системы уходят в никуда. Хозяин не видит «кто пишет», «грант до ЧЧ:ММ»,
   «ход идёт», «мозг деградировал», если текст не продублирован в чатлог.
2. **Рельс — набор скрытых секций.** `сессии`, `навигация`, «Внештат», бар
   учителя, шкала контекста (до первого ACP-события) — в коде есть, на экране нет.
3. **Роли не помечены в чатлоге.** Рот/мозг/руки видны только как три строки
   рельса; по ленте нельзя сказать, чей это шаг (руки? мозг?).
4. **Итог найма без истории.** Расписка живёт одной карточкой в ленте; журнала
   наймов по сессии (с диффами на приёмку) нет.
5. **Диалоги без единого стиля.** `SessionsPopup`, справка `ops_live`,
   `LabCanvas`, `QMessageBox` — разные рамки, шрифты, способы закрытия.
6. **Палитра раздвоена.** Компактный журнал runtime (`ops_live.py`) использует
   свою жёсткую палитру (`#1a1a1e`, `#5ee7ff`, Consolas), не связанную с
   `theme.py`.
7. **Композер: объявленный шрифт ≠ фактический** (`Cascadia Mono 12` в QSS
   против `Segoe UI 13` в `setFont`), а поле ввода — единственная точка,
   где шрифт меняется на UI-шрифт.
