## Platform

web

> Условно: `web` — это среда **прототипов** (статический HTML). Настоящая цель —
> десктопное приложение Windows на Qt Widgets + QSS (PySide6), которое по
> прототипам собирает локальная команда хозяина. Мобильных и планшетных вариантов нет.

## Stack

Прототипы: статический HTML/CSS/vanilla JS, самодостаточные (открываются
двойным кликом, без сборки, без CDN, без сетевых вызовов). Цель переноса:
Qt Widgets + QSS (PySide6). Решение хозяина из `CLAUDE.md`.

## Users

Один человек — **хозяин** (Юрий), русскоязычный. Десктоп Windows,
1440×900 и 1920×1080, клавиатура прежде мыши. Работает каждый день:
ставит ИИ-агентам работу по своим проектам одним текстом, решает закон,
выдаёт гранты на запись, принимает дифф. Разработчик системы — свободно
читает технические термины, но на основном экране хочет видеть суть, а не
внутренности.

## Product Purpose

FractalOS — десктопная оболочка, в которой хозяин работает с ИИ-агентами над
своими проектами: разговаривает с **ртом** в одном чате, а объёмную работу рот
передаёт **рукам** по найму через закрытый бриф **мозга**.

Успех интерфейса — в словах хозяина, по приоритету:
1. видно, что всё работает: здоровье частей честно (работает / деградирует /
   лежит и почему), без шума;
2. понятно, из чего состоит система: карта частей и связей;
3. инварианты ролей видны по интерфейсу, а не по документации;
4. есть журнал сессий: что было, что сделали руки, чем кончилось, где дифф
   на проверку;
5. отличный композер и чатлог;
6. другие полезные функции — только с обоснованной пользой для хозяина.

## Positioning

Не «чат с ИИ», а рабочее место с **законом ролей**, который система соблюдает
буквально: один чат; найм = закрытый бриф → песочница → расписка; руки правят
копию дерева и отдают дифф; один писатель на проект; запись вне песочницы —
только по гранту хозяина. Интерфейс обязан делать этот закон видимым.

## Operating Context

- Роли: хозяин (человек), рот (чат; по умолчанию Grok, запасной Flash),
  мозг (слот `brain_axis`: Grok или Flash), руки (DSH по найму: mux `:11436` +
  воркеры slim / lean / full), учитель (правила, не персона).
- Проекты-корни: fractal-корни (FractalOS, fractalmem, fractalprofit) — через
  копию и дифф; внешние (например, metrprod) — по своим правилам. Проект
  выбирается хозяином; руки работают в корне проекта.
- Поток найма: бриф → старт → прогресс → итог → **файл-расписка**
  (`done.md`, важнее кода возврата) → дифф. Незавершённое → повторный найм
  или аварийный мозг.
- Грант: `/approve <минуты>`, каждое действие — разово; снимает `/approve off`.
- Слэш-команды окна (~35), сессии рта, память fractalmem, атлас (103 узла).

## Capabilities and Constraints

- Инварианты ролей (закон, `docs/PRODUCT-MODEL.md`): один чат (один ChatPane);
  рот — это чат; руки не пишут вне песочницы без гранта; грант выдаёт только
  хозяин; рот и руки гранта себе не дают; один писатель (занято → отказ, не
  очередь); закон окна правит только хозяин.
- Реализуемость: всё собирается в Qt Widgets + QSS. Нельзя: blur-стекло,
  сложные CSS-фильтры, WebGL, тяжёлые анимации. Анимации короткие и
  отключаемые. Для каждого компонента — строка «Qt: как собрать».
- Тёмная тема. Русский текст интерфейса.
- Память показывается только как «работает / нет / сколько помнит по
  проекту» — без механики (атомы, пины, кандидаты, оферы, метки классификаторов).
- Внутренние логи и отладочный шум — не на основном экране.
- Данные в прототипах — выдуманные, но правдоподобные; бэкенда и сети нет.

## Product Principles

1. **Честность статуса важнее спокойствия.** Работает / деградирует / лежит —
   и почему; тишина только тогда, когда действительно всё в порядке.
2. **Закон видно в интерфейсе.** Кто что может и чего не может — читается с
   экрана в момент действия, а не из документации.
3. **Внутренности — вниз.** Механика памяти, классификаторы, логи runtime —
   за явным действием, не на основном экране.
4. **Один чат — центр.** Всё остальное (здоровье, журнал, дифф, грант) живёт
   вокруг чата и ведёт к нему, а не заменяет его.
5. **Qt — условие, а не пожелание.** Решение, которое нельзя собрать в
   Qt Widgets + QSS, не является решением.

## Accessibility & Inclusion

- Клавиатура прежде мыши: каждое действие доступно с клавиатуры, фокус виден.
- Контраст текста не ниже WCAG AA (4.5:1) для чтения, 3:1 — для крупного и
  нетекстовых элементов.
- Анимации короткие и отключаемые.
- Рабочие масштабы Windows: 1440×900 и 1920×1080 (с учётом системного
  DPI-масштабирования).
